# BlockPick Admin 운영 매뉴얼

---

## 1. 시스템 개요

### 1.1 서비스 소개

BlockPick Admin은 블록픽 게이밍 플랫폼의 관리자 대시보드입니다. 사용자, 게임, 상품, 블록체인 컨트랙트, 파일 스토리지, 시스템 모니터링을 통합 관리할 수 있습니다.

### 1.2 기술 스택

| 구분 | 기술 |
| --- | --- |
| 프레임워크 | Next.js 16.1.6 (App Router) |
| 언어 | TypeScript 5.9 |
| UI 라이브러리 | shadcn/ui + Tailwind CSS |
| 상태관리 | TanStack React Query 5 |
| 폼 처리 | React Hook Form + Zod |
| 차트 | Recharts |
| 아이콘 | Lucide React |
| 테마 | next-themes (다크/라이트 모드) |

### 1.3 백엔드 API

- **Base URL**: `https://api-dev.blockpick.net`
- **인증 방식**: Bearer Token (JWT)
- **프로토콜**: REST API (JSON)

> ⚠️ 이 프로젝트는 프론트엔드 전용입니다. 별도의 로컬 데이터베이스 없이 외부 BlockPick API 서버에 의존합니다.

## 2. 환경 설정

### 2.1 필수 환경 변수

프로젝트 루트에 `.env.local` 파일을 생성하고 아래 값을 설정합니다.

```
NEXT_PUBLIC_API_URL=https://api-dev.blockpick.net
NEXT_PUBLIC_APP_NAME=BlockPick Admin
```

| 변수명 | 설명 | 필수 |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | 백엔드 API 서버 주소 | ✅ |
| `NEXT_PUBLIC_APP_NAME` | 앱 표시 이름 | 선택 |

### 2.2 설치 및 실행

```bash
# 의존성 설치
pnpm install

# 개발 서버 실행 (http://localhost:3000)
pnpm dev

# 프로덕션 빌드
pnpm build

# 프로덕션 서버 실행
pnpm start

# 린트 검사
pnpm lint
```

### 2.3 이미지 도메인 설정

S3 스토리지 이미지를 표시하기 위해 `next.config.ts`에 아래 도메인이 허용 등록되어 있습니다.

```
blockpick-dev-storage.s3.us-west-2.amazonaws.com
```

> 스토리지 버킷이 변경되면 `next.config.ts`의 `images.remotePatterns`를 함께 수정해야 합니다.

## 3. 인증 및 권한

### 3.1 로그인 흐름

```
사용자 → 이메일/비밀번호 입력 → POST /admin/auth/login
→ accessToken + refreshToken 발급 → localStorage 저장
→ 대시보드로 리다이렉트
```

1. `/login` 페이지에서 이메일과 비밀번호를 입력합니다.
2. 인증 성공 시 `accessToken`과 `refreshToken`이 `localStorage`에 저장됩니다.
3. 모든 API 요청에 `Authorization: Bearer {accessToken}` 헤더가 자동 포함됩니다.
4. 토큰 만료 시 자동으로 `refreshToken`을 사용해 갱신을 시도합니다.
5. 갱신 실패 시 로그인 페이지로 리다이렉트됩니다.

### 3.2 사용자 역할

| 역할 | 코드 | 설명 |
| --- | --- | --- |
| 일반 사용자 | `USER` | 기본 사용자 |
| 관리자 | `ADMIN` | 관리 기능 접근 가능 |
| 파트너 | `PARTNER` | 파트너/벤더 |
| 슈퍼 관리자 | `SUPER_ADMIN` | 모든 권한 보유 |

### 3.3 개발 모드

개발 환경(`NODE_ENV=development`)에서는 로그인 화면에 **Dev Mode** 버튼이 표시됩니다. 클릭 시 Mock 토큰으로 인증을 우회하여 빠르게 테스트할 수 있습니다.

> ⚠️ 프로덕션 환경에서는 Dev Mode가 비활성화됩니다.

## 4. 메뉴별 기능 가이드

### 4.1 대시보드 (`/dashboard`)

메인 화면으로 플랫폼의 전반적인 현황을 한눈에 파악할 수 있습니다.

**제공 정보:**

- **통계 카드**: 전체 사용자 수, 게임 수, 상품 수, 시스템 상태
- **차트**: 사용자 가입 추이, 게임 생성 추이, 매출 추이, 상품 등록 추이
- **활동 타임라인**: 최근 시스템 활동 이력
- **최근 항목**: 최근 생성된 게임 및 사용자

---

### 4.2 사용자 관리 (`/users`)

플랫폼에 등록된 사용자를 관리합니다.

**기능:**

| 기능 | 설명 |
| --- | --- |
| 사용자 목록 조회 | 테이블 형태로 전체 사용자 목록 표시 (정렬/필터/페이지네이션) |
| 사용자 검색 | 이메일, 이름으로 검색 |
| 필터링 | 역할(USER/ADMIN/PARTNER/SUPER_ADMIN), 상태(활성/비활성), 가입일 범위 |
| 사용자 생성 | 이메일, 비밀번호, 닉네임, 역할을 입력하여 새 사용자 생성 |
| 사용자 수정 | 닉네임, 역할, 상태 변경 |
| 사용자 삭제 | 확인 다이얼로그 후 삭제 |
| 상세 보기 | 사용자 상세 정보 다이얼로그 |
| 역할 변경 | 사용자 역할을 일괄 또는 개별 변경 |

**조작 방법:**

1. 우측 상단 `사용자 추가` 버튼으로 새 사용자를 생성합니다.
2. 테이블 행의 `⋯` 메뉴에서 수정/삭제/상세보기를 선택합니다.
3. 상단 필터바에서 역할, 상태, 날짜 범위를 조합하여 필터링합니다.

---

### 4.3 게임 관리 (`/games`)

블록픽 게임을 생성하고 관리합니다.

**게임 타입:**

| 타입 | 설명 |
| --- | --- |
| `PRIME` | 프라임 게임 |
| `NORMAL` | 일반 게임 |
| `GIVEAWAY` | 경품 게임 |

**게임 상태:**

| 상태 | 설명 |
| --- | --- |
| `DRAFT` | 초안 (아직 시작 전) |
| `ACTIVE` | 진행 중 |
| `ENDED` | 종료됨 |
| `SETTLED` | 정산 완료 |
| `CANCELLED` | 취소됨 |

**기능:**

| 기능 | 설명 |
| --- | --- |
| 게임 목록 | 썸네일, 타입, 카테고리, 상태, 보상 포인트 표시 |
| 게임 생성 | 이름, 설명, 타입, 카테고리, 시작/종료 시간, 보상 포인트, 이미지 설정 |
| 게임 수정 | 게임 정보 변경 (진행 중인 게임도 일부 수정 가능) |
| 게임 삭제 | `DRAFT` 상태의 게임만 삭제 가능 |
| 강제 종료 | `ACTIVE` 상태의 게임을 즉시 종료 |
| 정산 | `ENDED` 상태의 게임 결과를 정산 |
| 리더보드 | 게임별 참여자 순위 확인 (`/games/[id]/leaderboard`) |
| 연결 상품 | 게임에 연결된 상품 관리 (`/games/[id]/products`) |

**조작 방법:**

1. `게임 추가` 버튼으로 새 게임을 생성합니다.
2. 게임 생성 시 스마트 컨트랙트 배포가 자동으로 진행될 수 있습니다 (Polygon 네트워크).
3. 배포 상태는 실시간으로 추적되며, 트랜잭션 해시와 컨트랙트 주소가 표시됩니다.
4. `ACTIVE` 게임을 강제 종료하려면 `⋯` → `강제 종료`를 선택합니다.
5. `ENDED` 게임을 정산하려면 `⋯` → `정산`을 선택합니다.

## 6. 운영 가이드

### 6.1 일상 운영 체크리스트

**매일 확인 사항:**

- [ ]  대시보드에서 전체 시스템 상태 확인
- [ ]  모니터링 > 시스템 헬스 확인 (CPU/메모리/DB 연결)
- [ ]  모니터링 > 로그에서 ERROR 레벨 로그 확인
- [ ]  모니터링 > 미발행 이벤트 및 실패 트랜잭션 확인
- [ ]  진행 중인 게임(`ACTIVE`) 상태 점검

**주간 확인 사항:**

- [ ]  사용자 가입 추이 확인
- [ ]  게임 생성/종료/정산 현황 확인
- [ ]  블록체인 컨트랙트 배포 실패 건 확인
- [ ]  스토리지 용량 및 파일 관리

### 6.2 게임 라이프사이클 관리

```
DRAFT → ACTIVE → ENDED → SETTLED
  │                  │
  └── 삭제 가능       └── 강제 종료 가능
```

1. **게임 생성** (`DRAFT`): 게임 정보를 입력하고 생성합니다. 스마트 컨트랙트 배포가 함께 진행됩니다.
2. **게임 시작** (`ACTIVE`): 설정된 시작 시간에 자동으로 활성화되거나, 수동으로 활성화합니다.
3. **게임 종료** (`ENDED`): 종료 시간에 자동 종료되거나, `강제 종료` 기능으로 즉시 종료합니다.
4. **정산** (`SETTLED`): 종료된 게임의 결과를 확인하고 보상을 정산합니다.

> ⚠️ 강제 종료는 되돌릴 수 없습니다. 신중하게 사용하세요.

### 6.3 사용자 역할 관리 가이드

| 상황 | 조치 |
| --- | --- |
| 새 관리자 추가 | 사용자 생성 시 역할을 `ADMIN`으로 설정 |
| 파트너사 계정 생성 | 역할을 `PARTNER`로 설정 |
| 권한 상승 필요 | 사용자 목록에서 역할 변경 |
| 계정 비활성화 | 사용자 상태를 비활성으로 변경 (삭제하지 않음) |

### 6.4 블록체인 트러블슈팅

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 컨트랙트 배포 `PENDING` 장기 지속 | 네트워크 혼잡 또는 가스비 부족 | 백엔드 팀에 문의하여 트랜잭션 상태 확인 |
| 배포 상태 `FAILED` | 컨트랙트 코드 오류 또는 네트워크 장애 | 로그 확인 후 재배포 시도 |
| 트랜잭션 조회 불가 | 잘못된 트랜잭션 해시 | 해시 값 재확인 |
| 컨트랙트 검증 실패 | 소스 코드 불일치 | 백엔드 팀과 소스 코드 확인 |

### 6.5 장애 대응

**1단계: 상황 파악**

- 모니터링 > 시스템 헬스 확인
- 모니터링 > 로그에서 ERROR 검색
- 대시보드에서 통계 이상 여부 확인

**2단계: 긴급 조치**

- 진행 중인 게임이 영향 받는 경우 → `강제 종료` 고려
- 인증 장애 시 → 백엔드 API 서버 상태 확인

**3단계: 보고 및 복구**

- 장애 내용, 영향 범위, 조치 사항을 기록
- 백엔드 팀에 상세 로그와 함께 전달

## 10. FAQ

### Q: 로그인이 되지 않습니다.

- API 서버(`NEXT_PUBLIC_API_URL`)가 정상 동작하는지 확인하세요.
- 이메일과 비밀번호가 올바른지 확인하세요.
- 브라우저 콘솔에서 네트워크 에러를 확인하세요.

### Q: 게임을 삭제할 수 없습니다.

- `DRAFT` 상태의 게임만 삭제할 수 있습니다.
- `ACTIVE` 게임은 먼저 `강제 종료`한 후 처리하세요.

### Q: 이미지가 표시되지 않습니다.

- `next.config.ts`의 이미지 도메인 설정을 확인하세요.
- S3 버킷 접근 권한을 확인하세요.
- 브라우저 네트워크 탭에서 이미지 URL의 응답 상태를 확인하세요.

### Q: 블록체인 배포가 실패합니다.

- 모니터링 > 로그에서 관련 에러를 확인하세요.
- Polygon 네트워크 상태를 확인하세요.
- 백엔드 팀에 가스비 잔액과 컨트랙트 코드를 확인 요청하세요.

### Q: 데이터가 실시간으로 갱신되지 않습니다.

- React Query 캐시 유효시간(5분) 이내에는 캐시된 데이터가 표시됩니다.
- 페이지를 새로고침하거나, 설정에서 자동 새로고침을 활성화하세요.
